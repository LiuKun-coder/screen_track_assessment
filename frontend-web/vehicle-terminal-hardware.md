# 校园电动车监管系统｜车载终端硬件方案（基于 STM32）

本文给出两套可落地的车载终端方案，并列出关键器件清单（BOM 级别到具体型号），最后提供从 0 到 1 的硬件实现流程（原理图→PCB→固件→联调→小批量）。

---

## 1. 目标与边界

### 1.1 终端要实现的功能

- 定位：获取经纬度、速度、航向、时间（GNSS）
- 轨迹：按策略采样、断网缓存、联网补传
- 电子围栏：围栏规则下发到终端，本地判定进/出并告警
- 超速检测：本地实时判定，带滤波和持续时间阈值

### 1.2 哪些功能建议放在硬件端

- 可在硬件端完成（推荐端侧实现）：
  - 定位（GNSS 解算结果读取）
  - 超速检测（用 GNSS 速度或轮速）
  - 围栏进出判定（圆形/多边形点内判定）
  - 轨迹采样与缓存（Flash/TF）
- 更适合后端/平台完成（端侧只执行结果）：
  - 围栏绘制与策略管理（后台创建、版本控制、下发）
  - 轨迹回放、统计聚合、热力图、排行等（平台侧）

---

## 2. 总体架构（共用）

### 2.1 模块组成

- MCU：STM32（负责控制、存储、协议、策略）
- GNSS：GPS/北斗模块（UART）
- 通信：
  - 方案 A：4G Cat.1/NB-IoT（UART）
  - 方案 B：LoRa（SPI/UART）
- 存储：SPI NOR Flash（必选），TF（可选）
- 传感：IMU（可选但推荐），电压采样（ADC）
- 电源：车载电池宽压输入 → 5V/4.0V/3.3V 多路
- 结构：IP65/67 外壳、天线、线束/连接器、防拆

### 2.2 推荐上报数据

- 轨迹点：deviceId, ts, lat, lon, speed, heading, battery, gpsFixQuality
- 事件：overspeed_start/end, fence_enter/exit, power_cut, tamper, gps_lost

---

## 3. 方案 A：4G Cat.1 + GNSS（推荐“部署最省事”）

### 3.1 适用场景

- 不想布校园网关；希望“装上就能用”
- 允许 SIM 流量/物联网卡月租
- 室外/半室外为主，GNSS 可用

### 3.2 关键器件清单（建议版 BOM）

> 说明：以下为“可采购/可量产”的器件级 BOM，不展开到每颗电阻电容，但关键电源、保护、连接器、天线等均给到具体型号或可替代系列。

#### A. 主控与时钟

- MCU：
  - 首选低功耗：STM32L476RGT6（LQFP64, 1MB Flash/128KB RAM）
  - 备选性能更强：STM32F407VGT6（功耗更高，富余度大）
- 调试接口：2.54mm 排针或 Tag-Connect（TC2030）
- 外部晶振（可选，提升 RTC/时钟精度）：
  - 32.768kHz：NX3215SA-32.768K（或同等 12.5pF）
  - 主晶振：8MHz/16MHz（如 ECS-160-20-5PXDU）可选，L4 也可用内部 RC

#### B. 定位（GNSS）

- GNSS 模块（推荐二选一）：
  - Quectel L76K（GPS/北斗，UART，常用，成本友好）
  - u-blox NEO-M8N（多星座，成熟稳定）
- GNSS 天线：
  - 有源天线（推荐，遮挡环境更稳）：GPS/GNSS Active Antenna 3.3V 供电 + IPEX
  - 或陶瓷天线 + LNA（对布局要求更高）
- 天线座：IPEX/u.FL（如 Hirose U.FL-R-SMT）

#### C. 蜂窝通信（4G Cat.1）

- Cat.1 模组（推荐二选一）：
  - Quectel EC800M-CN（Cat.1，UART/USB，成熟）
  - SIMCom A7670C（Cat.1/Cat.4 系列需确认型号能力，建议选 Cat.1 子型号）
- SIM 卡座：
  - Nano-SIM：Molex 503398-1892（或同等抽屉式）
- LTE 天线：
  - 4G FPC/外置胶棒天线（覆盖全频段）+ IPEX
- 射频保护：ESD 二极管（如 Nexperia PESD5V0S1UL）

#### D. 存储

- SPI NOR Flash（用于断网缓存）：
  - Winbond W25Q64JVSSIQ（8MB）
  - 可上 W25Q128（16MB）提升离线能力
- TF 卡座（可选）：Amphenol / TE 常规 microSD 卡座

#### E. 传感与防拆（建议）

- IMU（建议选低功耗/抗漂移更好的一代）：
  - TDK ICM-42688-P（SPI/I2C）
  - 备选：Bosch BMI270
- 防拆开关（可选）：
  - 轻触开关：Omron B3U 系列（壳体开盖触发）
- 蜂鸣器/指示灯（可选）：
  - 有源蜂鸣器 3.3V
  - RGB LED（如 SK6812-mini，注意 EMI 与供电）

#### F. 电源与保护（关键）

> 车载电池常见 36/48/60V，必须用高压降压与浪涌防护。蜂窝模组有 2A+ 脉冲电流需求，电源必须“抗跌落”。

- 输入保护：
  - 保险丝：自恢复保险丝（如 MF-R110）或贴片保险丝
  - 反接保护：理想二极管方案（P-MOS + 控制器）或大功率肖特基（效率差）
  - TVS：SMBJ58A（48/60V 系统按实际电池满电电压选型）
- 高压降压到 5V：
  - TI LM2596HV-5.0（60V 输入上限版本，经典但体积偏大）
  - 或更现代高压同步降压（看成本/体积）：TI LM5164（100V，效率好）
- 5V → 4.0V（给蜂窝模组，峰值电流足够）：
  - 建议用 3A 级同步降压（按模组硬件设计指南选）
  - 并在模组 VBAT 旁放置：低 ESR 钽电容/聚合物电容（如 330uF/6.3V）+ 多颗 22uF/10uF
- 5V/4V → 3.3V（MCU/GNSS/IMU）：
  - 同步降压：TPS62162 / MP2307DN（根据电流与成本）
  - 或 LDO（若从 5V 降 3.3V 且电流较大不推荐）：AP2112K-3.3（小电流可用）
- 电压采样：
  - 分压电阻 + RC 滤波 → MCU ADC

#### G. 连接器与结构

- 车载线束连接器（推荐防水）：
  - M8/M12 防水航插（2~4 芯：电源/GND/可选 IO）
  - 或 JST-VH（不防水，适合壳体内）
- 外壳：PC+ABS 或铝壳，IP65/67，预留天线孔位
- 散热：蜂窝模组区域留铜皮+过孔阵列

## 4. 方案 B：LoRa + GNSS + 校园网关（推荐“内网可控/低成本流量”）

### 4.1 适用场景

- 校园希望私有化、内网传输
- 能接受布设 LoRa 网关（教学楼/宿舍区高点）
- 车辆数较多，希望降低持续流量成本

### 4.2 关键器件清单（建议版 BOM）

> 与方案 A 共用：MCU、GNSS、Flash、电源与保护、结构。差异主要在“通信模组”与“网关”。

#### A. LoRa 通信（终端侧）

- LoRa 模组（推荐二选一）：
  - Ebyte E22-900M30S（SX1262，功率高，UART 版易集成）
  - 或基于 SX1276 的成熟模组（如 E32 系列，注意新旧代差异）
- LoRa 天线：
  - 868/915MHz 胶棒天线或 FPC + IPEX（按地区频段与法规选）
- 射频匹配/ESD：按模组参考设计

#### B. LoRa 网关（校园侧，必需）

- 工业级网关（示例方向）：
  - RAKwireless / Dragino / Mikrotik（需选 LoRaWAN 网关或自定义协议网关）
- 服务器侧：
  - 选择 LoRaWAN（标准生态）或自定义 LoRa 协议（更轻量但要自研网关转发）

## 5. 两套方案对比（选型建议）

- 部署难度：
  - 4G Cat.1：低（插卡即可）
  - LoRa：中（需布网关/覆盖规划）
- 单车长期成本：
  - 4G：有月租/流量
  - LoRa：几乎无流量费（但有网关与运维）
- 实时性与容量：
  - 4G：强，带宽大
  - LoRa：适合“事件 + 低频轨迹”，不适合高频连续点位
- 适合您当前大屏：
  - 两者都适配；LoRa 方案建议更偏“事件驱动 + 低频轨迹”

## 6. 固件端实现建议（STM32 上的模块划分）

### 6.1 任务/模块（建议用裸机 + 定时器 或 FreeRTOS）

- GNSS 驱动：UART DMA + NMEA/二进制解析
- 速度/里程：GNSS 速度滤波；可选轮速输入捕获
- 轨迹采样策略：
  - 定时采样（如 2s/5s）
  - 或距离触发（移动超过 10m 记录）
  - 或转弯触发（航向变化超过阈值）
- 围栏判定：
  - 圆形：Haversine 距离 < 半径
  - 多边形：射线法点内判定
  - 结果：enter/exit 事件上报 + 本地落盘
- 超速检测：
  - 速度滑动窗口滤波
  - 触发条件：speed > limit 持续 T 秒（如 3s）
  - 恢复条件：speed < limit - hysteresis 持续 T 秒
- 存储：
  - 环形缓冲区写 Flash
  - 上报成功后标记清除（断点续传）
- 通信：
  - 4G：MQTT（推荐）或 HTTP；断线重连；心跳
  - LoRa：事件优先；轨迹采用压缩（差分/定点）降低空口负载
- 远程配置：
  - 下发围栏/限速/采样策略/固件版本
- 设备健康：
  - 电压、GNSS fix 状态、模块在线状态、重启原因统计

## 7. 从 0 到 1 怎么做（硬件落地流程）

### 阶段 0：需求冻结（1~3 天）

- 输出文档：
  - 场景边界：室外/室内比例、车辆数量、期望定位精度
  - 上报频率：轨迹点频率、事件实时性要求
  - 供电条件：电池电压范围、是否允许取电、安装位置
- 决策：
  - 选方案 A（4G）还是方案 B（LoRa）
  - 是否需要轮速传感器（遮挡场景更稳）

### 阶段 1：原型验证（1~2 周）

- 买开发板/模块快速跑通：
  - STM32 Nucleo（或最小系统板）
  - GNSS 模块（L76K/NEO-M8N）
  - 通信模组（EC800M 或 LoRa 模组）
  - SPI Flash 小板
- 验证要点：
  - GNSS 首次定位时间、遮挡漂移
  - 超速检测与去抖策略
  - 断网缓存与补传可用性
  - 电源脉冲电流下是否复位（蜂窝最容易出问题）

### 阶段 2：原理图设计（1~2 周）

- 关键设计点（必须按参考设计）：
  - 蜂窝模组 VBAT 供电：走线宽、地回流完整、大电容贴近
  - GNSS 射频走线与天线隔离：远离开关电源、电感、蜂窝天线
  - TVS/反接/保险丝/浪涌：必须有
  - 调试/量产接口：SWD + 串口日志口（建议预留）
- 输出物：
  - 原理图、BOM、关键布局约束说明

### 阶段 3：PCB Layout（1~2 周）

- 建议：2 层可做但风险大；推荐 4 层（电源/地更稳，GNSS/蜂窝更可靠）
- 重点：
  - 电源模块与射频区隔离
  - 天线座周围 Keepout
  - 蜂窝模组下方禁走线/禁铺铜按指南
- 输出：
  - Gerber、装配图、钢网、位号图

### 阶段 4：打样与焊接（1~2 周）

- 先做 5~10 套工程样机
- 上电自检顺序：
  - 空载电源纹波/温升
  - GNSS 输出是否正常
  - 通信注册/入网是否稳定
  - 断电/瞬态是否复位

### 阶段 5：固件工程化（2~4 周）

- 基础设施：
  - 日志系统、参数存储、看门狗、OTA（可选）
- 业务逻辑：
  - 轨迹采样 + 围栏 + 超速 + 事件队列
- 可靠性：
  - 断点续传、异常重启恢复、Flash 磨损均衡（至少做分区轮转）

### 阶段 6：联调（与后端/前端）

- 协议联调：
  - 统一字段命名、时间戳、坐标系（WGS84/GCJ02）
  - 事件状态机（超速开始/结束、围栏进/出）
- 前端大屏联动：
  - 实时点位、事件列表、趋势统计

### 阶段 7：道路/校园实测（2~4 周）

- 指标：
  - 定位可用率（Fix 成功比例）
  - 轨迹“漂移”与断点
  - 超速误报率/漏报率
  - 电源稳定性（冷启动、骑行震动、断电）
- 迭代：
  - 调采样频率与滤波参数
  - 调天线位置/外壳结构

### 阶段 8：小批量与量产导入

- 量产测试工装：
  - 串口自动化测试：GNSS/通信/Flash/ADC
  - 条码/设备ID 烧录
- 供应链：
  - 模组/MCU 主料备选型号
- 合规提示：
  - 蜂窝通信设备、无线电发射需关注法规与入网要求（尤其 LoRa 频段与功率）

## 8. 推荐默认参数（便于第一版落地）

- 轨迹采样：移动中 2s/点，静止 30s/点
- 超速阈值：例如 25km/h（按校规），持续 3s 触发，恢复滞回 2km/h
- 围栏：支持 1~8 个围栏（圆形优先，多边形次之）
- 缓存：8MB Flash 可存数万点（按压缩与字段设计不同）

## 9. 下一步你需要决定的 3 件事（我就能把 BOM 再收敛到“唯一选型”）

1) 校园是否允许长期使用 4G 物联卡？（决定方案 A/B）
2) 车辆主要在室外还是会进地下/室内？（决定是否上轮速/IMU 强化）
3) 终端供电是“直连电动车电池”还是“自带电池”？（决定电源与结构复杂度）
