校园电动车违规管理系统 后端接口文档
 注：因为我对后端接口的定义不是很熟练，所以本文档接口的定义时拜托ai写的，我写要求的时候强调了要写的详细、ai也能看懂。因此，如果这个文档你觉得阅读有困难，直接丢给ai帮你解读我觉得也是ok的。

基础信息

基础URL: `http://localhost:8080/api`
认证方式: JWT Token (Bearer Token)
数据格式: JSON
字符编码: UTF8

通用响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2024-06-01T10:00:00Z"
}
```

错误码说明

| 错误码 | 说明 |
|||||
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未授权/Token无效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

1.1 用户登录
接口: `POST /auth/login`
描述: 用户登录认证
请求参数:
```json
{
  "username": "string",
  "password": "string",
  "remember": "boolean"
```

注意事项

1. 认证要求: 除登录、注册、发送验证码接口外，其他所有接口都需要在请求头中携带有效的JWT Token
2. 权限控制: 管理员接口需要管理员权限，普通用户无法访问
3. 分页参数: 所有列表接口都支持分页，默认page=1, size=10
4. 时间格式: 所有时间字段使用ISO 8601格式 (YYYY-MM-DDTHH:mm:ssZ)
5. 文件上传: 支持的文件类型包括图片(jpg, png, gif)、视频(mp4, avi)、文档(pdf, doc, docx)
6. 错误处理: 所有接口都会返回统一的错误格式，前端需要根据code字段判断请求是否成功

开发建议

1. 数据库设计: 建议使用MySQL或PostgreSQL作为主数据库
2. 缓存策略: 建议使用Redis缓存热点数据，如用户信息、统计数据等
3. 文件存储: 建议使用对象存储服务(如阿里云OSS、腾讯云COS)存储上传的文件
4. 安全措施: 
   实现JWT Token刷新机制
   添加接口访问频率限制
   对敏感数据进行加密存储
   实现SQL注入防护
5. 日志记录: 建议记录所有关键操作日志，便于问题排查和审计
6. 性能优化: 
   对大量数据的查询进行分页
   对复杂查询添加数据库索引
   使用连接池优化数据库连接
