# 校园电动车违规管理系统 - 后端构建文档

本文档基于前端项目需求及接口文档，为开发人员（或AI助手）提供详细的 Spring Boot 后端构建指南。

## 1. 技术栈选型

*   **开发语言**: Java 17+
*   **核心框架**: Spring Boot 3.2.x
*   **持久层**: MyBatis-Plus 3.5.x
*   **数据库**: MySQL 8.0
*   **权限认证**: JWT (JSON Web Token)
*   **工具库**: Lombok, Hutool, FastJson2 (或 Jackson)
*   **API文档**: Knife4j (Swagger 3)

## 2. 数据库设计 (Database Design)

请在 MySQL 中创建一个名为 `scs_db` 的数据库，并执行以下 SQL 脚本以初始化表结构。

```sql
CREATE DATABASE IF NOT EXISTS scs_db DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE scs_db;

-- ----------------------------
-- 1. 系统用户表 (普通用户/学生)
-- ----------------------------
create table sys_user (
    id bigint auto_increment primary key comment '主键ID',
    username varchar(50) not null unique comment '用户名/学号',
    password varchar(100) not null comment '加密后的密码',
    name varchar(50) comment '真实姓名',
    phone varchar(20) comment '手机号',
    email varchar(100) comment '邮箱',
    avatar varchar(255) comment '头像URL',
    department varchar(50) comment '所属学院/部门',
    user_type varchar(20) default 'student' comment '用户类型: student, teacher, staff',
    status varchar(20) default 'active' comment '状态: active, disabled',
    create_time datetime default current_timestamp comment '创建时间',
    update_time datetime default current_timestamp on update current_timestamp comment '更新时间',
    deleted tinyint default 0 comment '逻辑删除: 0未删除 1已删除'
) comment '系统用户表';

-- ----------------------------
-- 2. 系统管理员表
-- ----------------------------
create table sys_admin (
    id bigint auto_increment primary key comment '主键ID',
    username varchar(50) not null unique comment '管理员账号',
    password varchar(100) not null comment '加密密码',
    name varchar(50) comment '管理员姓名',
    phone varchar(20) comment '联系方式',
    role varchar(20) default 'admin' comment '角色: admin, super_admin',
    department varchar(50) comment '所属部门(如保卫处)',
    create_time datetime default current_timestamp,
    deleted tinyint default 0
) comment '管理员表';

-- ----------------------------
-- 3. 违规记录表
-- ----------------------------
create table biz_violation (
    id bigint auto_increment primary key comment '违规ID',
    user_id bigint comment '关联用户ID (若能识别身份)',
    user_name varchar(50) comment '冗余用户姓名',
    violation_time datetime not null comment '违规时间',
    place varchar(100) not null comment '违规地点',
    type varchar(50) not null comment '违规类型: 超速, 违停, 逆行, 闯红灯',
    detail text comment '详细描述',
    penalty varchar(100) comment '处罚结果',
    status varchar(20) default 'processed' comment '状态: pending待处理, processed已处理',
    evidence_images json comment '证据图片URL数组 (JSON格式存储)',
    can_appeal tinyint default 1 comment '是否可申诉',
    appeal_status varchar(20) default 'none' comment '申诉状态: none, pending, approved, rejected',
    create_time datetime default current_timestamp,
    deleted tinyint default 0
) comment '违规记录表';

-- ----------------------------
-- 4. 申诉记录表
-- ----------------------------
create table biz_appeal (
    id bigint auto_increment primary key comment '申诉ID',
    violation_id bigint not null comment '关联违规ID',
    user_id bigint not null comment '提交人ID',
    appeal_number varchar(50) unique comment '申诉编号 AP2024...',
    platform varchar(20) default 'web' comment '来源: web, miniapp',
    reason varchar(50) comment '申诉原因类型',
    description text comment '申诉描述',
    contact_phone varchar(20) comment '联系电话',
    evidence_files json comment '证据文件 (视频/图片)',
    status varchar(20) default 'pending' comment '状态: pending, approved, rejected',
    reply_content text comment '管理员处理回复',
    handler_id bigint comment '处理管理员ID',
    handle_time datetime comment '处理时间',
    create_time datetime default current_timestamp
) comment '申诉记录表';

-- ----------------------------
-- 5. 轨迹记录表 (简化版)
-- ----------------------------
create table biz_track (
    id bigint auto_increment primary key,
    user_id bigint not null comment '用户ID',
    date date not null comment '日期',
    start_time datetime comment '开始时间',
    end_time datetime comment '结束时间',
    distance decimal(10, 2) comment '里程(km)',
    track_points longtext comment '轨迹点集合 (JSON大字段存储，包含 time, lat, lng, speed)',
    create_time datetime default current_timestamp
) comment '每日轨迹主表';

-- ----------------------------
-- 6. 电子围栏表
-- ----------------------------
create table biz_fence (
    id bigint auto_increment primary key,
    name varchar(100) not null,
    range_desc varchar(255) comment '范围文字描述',
    coordinates text comment '围栏坐标点集合 (JSON: [{lat,lng},...])',
    status varchar(20) default 'active' comment '状态',
    create_time datetime default current_timestamp
) comment '电子围栏配置表';

```

### 4.2 统一响应体 (common/utils/Result.java)
```java
@Data
public class Result<T> {
    private Integer code;
    private String message;
    private T data;
    private String timestamp;

    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.setCode(200);
        r.setMessage("success");
        r.setData(data);
        r.setTimestamp(LocalDateTime.now().toString());
        return r;
    }

    public static <T> Result<T> error(Integer code, String msg) {
        Result<T> r = new Result<>();
        r.setCode(code);
        r.setMessage(msg);
        r.setTimestamp(LocalDateTime.now().toString());
        return r;
    }
}
```

## 5. 核心模块实现指南

### 5.1 用户认证模块 (Auth)
*   **Controller**: `AuthController`
    *   `/login`: 接收 `LoginDTO`，校验账号密码。成功生成 JWT Token 返回。
    *   `/userInfo`: 解析 Token 获取 userId，查询数据库返回 `UserVO`。
*   **Service**: `AuthService`
    *   实现登录逻辑：先查 `sys_admin`，若无再查 `sys_user`，区分角色。
*   **技术点**: 使用拦截器 `HandlerInterceptor` 拦截所有非 `/auth/**` 请求，校验 Header 中的 Token。

### 5.2 违规管理模块 (Violation)
*   **Controller**: `ViolationController`
    *   `GET /violations/reports`: 大厅列表，支持分页与筛选 (QueryWrapper 动态拼接)。
    *   `GET /violations/my`: 获取当前登录用户的违规记录。
*   **Service Logic**:
    *   列表查询使用 MyBatis-Plus 的 `Page<Violation>` 分页对象。
    *   `evidence_images` 字段在 Entity 中定义为 String (JSON字符串)，在返回给前端时，可封装在 VO 中转为 `List<String>`。

### 5.3 申诉模块 (Appeal)
*   **流程**: 用户提交 -> 状态 `pending` -> 管理员审核 -> 状态 `approved`/`rejected`。
*   **关联**: 提交申诉时，校验对应的 `violation_id` 是否属于当前用户，且是否在可申诉期内。
*   **文件**: 证据上传接口先调用 `/upload` 返回 URL，再将 URL 存入申诉表。

### 5.4 大屏统计模块 (Screen)
*   **复杂查询**: 需要编写自定义 SQL (Mapper XML) 进行数据聚合。
    *   `countByDate`: 统计今日/本周违规。
    *   `groupByType`: 按违规类型分组统计通过率。
    *   建议创建 `ScreenStatsVO` 专门承接大屏数据结构。

## 6. 开发建议

1.  **代码生成器**: 推荐使用 MyBatis-Plus Generator 快速生成 Controller/Service/Mapper/Entity 代码。
2.  **JSON 处理**: 对于 MySQL 中的 JSON 字段 (如 evidence, track_points)，建议在 Entity 中添加 `ToTableField(typeHandler = JacksonTypeHandler.class)` 或是手动在 Service 层转换。
3.  **跨域处理**: 在 `WebMvcConfig` 中添加 `CorsRegistry` 配置，允许前端 `localhost:8080` (或其他端口) 的跨域访问。
    ```java
    @Override
    public void addCorsMappings(CorsRegistry registry) {
         registry.addMapping("/**")
                 .allowedOriginPatterns("*")
                 .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                 .allowCredentials(true);
    }
    ```
